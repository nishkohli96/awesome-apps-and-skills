# Design Brief: Awesome Apps & Skills website

Paste this whole file into the design tool. It is self-contained. The product plan it comes from is in [website-plan.md](website-plan.md).

## 1. What this is

A fast, trustworthy, human-curated directory of Claude skills, MCP servers, apps, web tools and learning resources. People arrive with a task in mind ("I need a video editor", "what skills exist for SEO?") and should find something good within 30 seconds.

There are **no per-tool detail pages**. Every tool card links straight to the tool's own website, so the card itself has to carry all the information.

## 2. Audience and personality

**Audience:** developers, designers and founders who already use Claude Code or other AI tools. They scan quickly, distrust marketing language, expect keyboard shortcuts and expect dark mode.

**Personality:** editorial and curated, like a well-run reading list or a design magazine crossed with a developer tool. Calm, confident, a little warm. It should feel like it was assembled by a person with taste, not generated by a startup template.

**Avoid:** purple-blue gradients, glassmorphism everywhere, stock illustrations of robots or brains, identical card grids with no hierarchy, autoplaying anything, popups, cookie banners (there are none).

## 4. Pages to design

For each page, deliver desktop (1440px) and mobile (375px), in light and dark.

### 4.1 Appbar (every page)
Left: logo and wordmark (home link). Centre: search field, placeholder "Search 150+ tools, skills and apps", with a `/` or Cmd/Ctrl+K hint. Right: New, Favourites (heart with count), Submit, a GitHub star button, and a three-way theme toggle (light / dark / system). Sticky, slight blur on scroll, border only after scrolling. On mobile: logo, search icon (opens full-screen search), menu button; the theme toggle moves into the menu.

### 4.2 Home
1. **Hero:** a headline, one subline, a large search field (same component as the appbar), three to five quick-pick chips ("Claude skills", "MCP servers", "Free", "Video", "Coding"), and a live stat line ("152 tools · 13 categories · updated this week"). Headline candidate: "The tools you haven't heard of yet, but will use this week."
2. **Category grid:** 13 cards. Each has an emoji or icon, the name, the one-line description, the tool count, and two or three subcategory names. The whole card is a link. Handle the 41-tool and 1-tool cases gracefully.
3. **Browse by type strip:** Skills, MCP servers, Apps, Web tools, Libraries, Guides, with counts.
4. **New this week:** 6 to 8 cards.
5. **Newsletter signup:** one field, one line of copy, one privacy line.
6. **Sponsor slot:** one clearly labelled "Sponsored" card position, designed in but hidden at launch.
7. **Footer:** category links, About, Submit, Privacy, GitHub, RSS, and "Not affiliated with Anthropic".

### 4.3 Category page
- Header: emoji, title, description, tool count, breadcrumb.
- **Tag bar** at the top: the most-used tags in that category as chips with counts, horizontally scrollable on mobile, with a "Show all tags" expander. Clicking a tag filters; clicking again clears it; multiple tags combine as AND. Selected tags appear in the URL.
- Beside the tag bar: type filter (multi-select), pricing filter, sort (A–Z, newest).
- Subcategory sections: a heading with a count and a grid of cards. A sticky side list on desktop (dropdown on mobile) jumps between subcategories. When a filter is active, subcategories with no matches collapse.
- Always-visible result count and "Clear filters" while filtering.
- Empty state for filter combinations with no results.

### 4.4 Search
- Dropdown under the appbar field: the top 8 results with a type icon, name, one-line description and category. Arrow keys and Enter work, Esc closes. States: empty (suggest popular tags), typing, results, no results (offer "Submit a tool").
- Full results page `/search?q=` with the same filters as a category page, results grouped by category.

### 4.5 Tool card (the most important component)
Because there is no detail page, the card shows everything:
- Type badge, name (links out), favicon.
- Description clamped to 3 lines, with a "more" toggle that expands it in place.
- All tags as clickable chips (first three, then a `+N` that expands).
- Pricing pill if present, and a subcategory label (needed on search and tag pages).
- Footer: a heart (favourite) and an outbound "Visit" arrow. Name and Visit both open the tool in a new tab.
- "New" badge for entries added in the last 14 days.
- Required states: default, hover, keyboard focus, favourited, new, sponsored, no pricing, description expanded, tags expanded.
- The sponsored variant uses the same card with a clear "Sponsored" label and must never be styled to look like organic content.

### 4.6 Other pages (lighter treatment is fine)
Favourites (with an empty state), Submit (links to a GitHub issue or PR), About, a custom 404 with search, and tag and type pages (these reuse the category layout).

## 5. Theme

Three-way toggle: light, dark, system (default). Define all colours as tokens for both themes, designed together. Both must meet WCAG AA contrast (4.5:1 body text, 3:1 UI borders). Check the type-badge colours in both themes.

## 6. Visual direction

- **Typography:** a distinctive but readable sans for UI and headings, an optional serif or display face for the hero headline, a mono face for tags and counts. A tight, deliberate type scale.
- **Colour:** one strong accent. The repo's Claude-orange (#d97757, used for skill badges) could anchor the brand. Neutral greys with a subtle warm tint. Type badges stay muted so a page of cards doesn't look like a rainbow.
- **Layout:** generous whitespace, 12-column grid, max content width around 1200px, 8px spacing system.
- **Surfaces:** flat with 1px borders rather than heavy shadows; a gentle shadow only on hover.
- **Motion:** small and purposeful (card hover lift, filter transitions, search dropdown fade), and it respects reduced-motion settings.
- **Icons:** one consistent outline set. The category emojis can serve as playful anchors.

## 7. Responsive and accessibility

Design mobile-first at 375px, then 768px, 1280px and 1536px. Cards go to one column on mobile; the tag bar scrolls horizontally. Visible focus rings everywhere, full keyboard operation, a skip-to-content link, and no information carried by colour alone.

## 8. Deliverables, in order

1. Design tokens (colour, type, spacing, radius, shadow) for both themes.
2. Component sheet: chips, buttons, badges, inputs, pills, theme toggle.
3. Tool card in every state listed in 4.5.
4. Appbar: desktop, mobile, and the theme toggle open.
5. Home page.
6. Category page: Media with a tag filter active, plus Automation & DevOps (1 tool) and an empty-filter state.
7. Search dropdown (all four states) and the search results page.
8. Favourites, Submit, About and 404 at a lighter level of detail.
